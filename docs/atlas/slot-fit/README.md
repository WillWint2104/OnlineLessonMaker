# The Slot Fit Atlas

The composition atlas answers *what pattern is this?* against the real quadratics lesson. This one
answers a different question against deliberately representative media: **is the object actually
inhabiting the slot the pattern gave it?**

Build it with `node scripts/slot-fit-atlas.mjs`. `SF_ONLY=image.portrait` renders one fixture or one
pattern; a filtered run says plainly that it cannot make the whole-atlas claims.

## The chain, and it runs one way only

```
pattern chooses an approved subdesign
  → the subdesign's slot determines the footprint (slotSpan, slotAnchor)
    → the media proves it can inhabit that footprint
      → the inspector verifies the relationship that was actually painted
```

The slot and the media stay separate concepts throughout. A graph being mathematically undistorted is
not enough for the layout to pass.

## The fixtures

Ten permanent objects, generated by `scripts/make-media-fixtures.mjs` into `docs/atlas/media/` and
committed. They are **regression assets, not mockups**: the same bytes produce the same proof next
month, and nothing is served by a third-party host. The clip is drawn on a canvas in Chromium and
captured with `MediaRecorder`, because there is no ffmpeg here and a clip downloaded from anywhere
would not be a regression asset.

| fixture | kind | aspect | class | authored presentation |
| --- | --- | --- | --- | --- |
| `graph.portrait` | plane | 1.200 | portrait | — (a graph's shape is its mathematics) |
| `graph.balanced` | plane | 0.857 | balanced | — |
| `graph.wide` | plane | 0.333 | wide | — |
| `image.portrait` | raster 900×1200 | 1.333 | portrait | 420px |
| `image.square` | raster 1100×1100 | 1.000 | balanced | 460px |
| `image.landscape` | raster 1600×900 | 0.563 | landscape | 720px |
| `video.landscape` | WebM 1280×720, 4s | 0.563 | landscape | 720px |
| `interactive.balanced` | instrument | 0.750 | balanced | 560px |
| `interactive.landscape` | instrument | 0.563 | landscape | 720px |
| `diagram.portrait` | SVG 480×640 | 1.333 | portrait | 380px |

**The authored presentation width is never the raster's pixel width.** A 900×1200 photograph is not a
request to be painted 900px wide. Under `contain` the painted width is
`min(presentationWidth, slotWidth)`; under `fill` the slot gives the width and this field is not
consulted.

## What is judged and what is photographed

Every legal combination is rendered and judged — the contract is only a contract if it is enforced
everywhere. The **golden proofs** are the ones that also carry an inspector photograph: one per
approved subdesign, and at least one per media family, chosen **before anything is measured** so the
choice cannot be a function of the result.

Filler prose is identical on every page, so the object is the only variable. That is also what makes
the subdesign-stability control meaningful: if a page changes its arrangement, the surface or the
aspect class changed, because nothing else did.

## Reading a proof

Each golden `<fixture>__<pattern>__<surface>.png` carries the slot dashed in blue, the painted object
outlined (green when it passes, red when it does not), any unclaimed width hatched where it actually
is — blue where the slot owns it, red where nobody does — and a panel reporting pattern, approved
subdesign, master grid, media slot, painted media, slot fit, anchor, shape preservation, unclaimed
internal width and the verdict. On a failure it also prints the diagnosis and the **legal actions**.

`slot-fit-report.json` carries every judged combination, including the ones with no photograph.

## What the contract cannot see

A `paired` row puts an object beside prose and the prose can run out first. Nothing horizontal is
unclaimed, every check passes, and the page still reads badly. The atlas measures that gap and prints
it, and **compares it to nothing** — prose length is content, and content may never decide a
composition. A threshold there would be the resolver coming back.
