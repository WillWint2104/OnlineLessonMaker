# Mathematics M1.1 — opening guide

Open `index.html` for actual application captures. Open the two linked learner lessons for the real exercise pages. Import their adjacent `lesson.json` into root `lesson-studio.html` to edit. Foundation means the existing `basic` value; question, example, collection and activity identities are preserved. The two lessons contain 36 independent questions each: three archetypes, eight Foundation and four Moderate problems each. Scaffold subparts count as one question. Every final and every worked line is numerically checked at six distinct values by an independent expression evaluator.

`meta.practiceLayout: "textbook"` enables distinct archetype destinations in the learner rail. Worked models remain internal tabs. Pathways are internal states, with optional `advanced` only when authored. Original M1 JSON without this field retains its prior view for compatibility. The current production lessons explicitly use Textbook. New controls are in Overview's inspector and the selected Practice question inspector. JSON remains supported; unknown metadata is preserved.

The exercise uses the shared question renderer: short questions flow in three/two/one columns. `question.layout` is auto/compact/wide/full; scaffolds and long prompts automatically span the width. Fonts stay readable; grid density does not shrink mathematics. Practice uses an Answer Hub rather than expanding inline answers. Native dialogs keep page/pathway/scroll state and keyboard focus. End-of-lesson unlock is a local pacing rule, not a security boundary or proof of mastery.

Final and worked policies are independent: autonomous/end/teacher/hidden. Teacher notes are never shipped in the student export. In teacher mode with hidden fallback, the relevant answer field is absent from exported lesson data and HTML, including an open JSON editor and answer dialogs. A deliberately available offline fallback includes that field in the static student file. Full working necessarily reveals its resulting final answer; separate policies cannot prevent inference from an allowed solution. Author JSON and review answer keys are teacher/reference material and must not be hosted with a genuinely protected lesson. These current review lessons use local end/autonomous policies; their source JSON and answers are intentionally public.

Present mode can display answers on the teacher's projector without changing any live session. Published files have no teacher sign-in/write controls. Local state is memory only. It is reset on importing another lesson. Images are authored SVG assets embedded through the existing image mechanism, not application-specific CSS drawings. Lesson Complete includes an optional authored next-lesson link.

## Optional live session implementation

No backend existed at audit time. A dependency-free Supabase preparation is included under `../../../supabase/`; see [deployment and security](../../../supabase/README.md). It is **not deployed or production certified**. The current lessons have no configured endpoint. Session screenshots exercise the real browser controls and actual handler with mocked authentication/persistence, clearly distinguished from a real Supabase deployment. Contract records are `class-session-results.json` and `class-browser-results.json`.

After configuration: teacher Auth sign-in + registered teacher authority; short class code is a read identifier, never write authority; server-gated answer delivery; five-second polling; four-hour expiry and End session; relocking withholds subsequent fetches. Previously delivered answers cannot be revoked from students' memory, screenshots or developer tools. Failed polling clears the session cache and restores authored fallback. Sessions do not persist across page reloads. Service-role secrets are server environment variables only; authoring rejects recognised secret/service-role keys.

Published lessons open from disk for local policies. Live sessions require HTTP(S), a deployed endpoint, an allowed browser origin and network access. YouTube playback is external and remains uncertified by blocked-request checks. No offline remote-video or live-service claim is made. M2 calculator, M3 sketch, History/Evidence/maps remain outside this work.

Verification receipts identify the implementation commit and application SHA. The 24-question density fixture and optional Advanced fixture test layout capabilities; they are not enrichment added to either classroom lesson. No recording was created.
