# Atlas V5 Stage 1 paper integration

The opted-in activity uses `layout: "geography-investigation"` on an explicitly Geography lesson with `meta.responseMode: "paper"`. Other layouts and subject renderers use their existing paths. Invalid opt-ins are rejected by import and publication validation. A live authoring draft with invalid settings uses the existing renderer and shows the host validation message.

In Study and standalone learner exports, an active Atlas investigation uses a compact header, an on-demand lesson outline, and Previous/Next activity controls after the activity. The outline and controls use the host's existing canonical navigation handlers and state. The host stage scrolls the activity in one flow. On wide screens the evidence and Question Workspace sit beside each other. At smaller widths they follow the reading order in one column. Edit keeps the existing inspector and preview, and front matter, completion and unflagged activities retain their original host presentation.

- GeoContentIntro reads the existing activity title, lede, ordered notes and practice note. Terms or headings introduce definitions. Untitled notes occupy the full reading width. Authors edit these in the normal inspector.
- GeoEvidenceSurface resolves `investigation.sourceRef` to a shared image or table in the current skill. The image uses the host Inspect source viewer and offline asset embedding. The table uses semantic headings and local keyboard-accessible scrolling. Source details uses the host provenance dialog for both. Labels, dated measures, essential interpretation and concise attribution are visible.
- GeoQuestionWorkspace reads the canonical question IDs, prompts and ordered parts. Optional public `guidance` is authored on the question or part. The drawer and selected part are view state in the host activity lifecycle. The optional map annotation controls are independent and persist during activity navigation. The host owns the lesson outline, previous and next activity, progress and answer policy.

The inspector can opt a standard paper Geography activity in or out, select shared evidence and edit source information, Help and map readings. An optional map has a percentage position for the Equator and an ordered set of labelled places with normalized image positions and geographic coordinates. Map annotations are presentation data. The underlying image supplies the geography. Rebuilding the host embed with `node scripts/build-geography-atlas.mjs` is idempotent.

The map fixture retains the exact V5 cartographic composition as a 1440 × 600 PNG rendered from the approved SVG. The existing viewer inspects those pixels. The location guide and selection controls remain on the activity map while the inspector shows the source image. The figure has six positions. Dhaka and Tokyo are selectable, as in V5. The ABS fixture preserves the four approved values and source data. Both fixtures are under the excluded docs/review deployment path.

Stage 2 should reuse the existing response store and approved question-part identity contract. This paper stage creates no learner response entries. The future combined policy, reload recovery and physical Huion acceptance are later work.
