# C2 — optional Mathematics visual attachments

Approved B2 contract, integrated into existing skill slides. No second hierarchy or renderer.

`slide.visuals` is an optional array of reusable givens. Each definition has a unique skill-local `id`, `kind` (`figure`, `table`, `image`), an instructional `description`, optional caption/provenance, and the existing matching payload. Figures retain `figure`; tables retain `stub/head/rows[{label,cells}]`; images retain `src/alt`. Unknown compatible metadata survives JSON round-trip. IDs must start with a letter and contain letters, numbers, underscore or hyphen. Definitions contain givens only; completion models belong to questions.

Examples/questions/structured subparts opt in with ordered `visualRefs: ["triangle-given"]`. References are required and skill-local. The parent displays shared evidence once, before parts; a part can extend it. An inherited reference is not repeated. Existing `q.figure` is not reinterpreted. Lessons without references keep their original content paths. Micro examples also retain their existing top-level companion visuals.

Default reading order is stem, referenced evidence with description/caption, parts, existing response workspace. No side-by-side placement is introduced. Instructional figures use bounded equal-scale fitting, never artwork cropping or independent-axis stretching. Images and wide tables use existing rendering. Circle/sector/solid assets remain authored images, not new native geometry capabilities.

`question.answerVisuals.final` and `.worked` are optional independent arrays of `{ref, completionCells?}`. `ref` resolves a skill definition; reserved `@questionTable` resolves that owner's existing `q.table`. Completion arrays match every row/column. Given cells cannot change; blank cells must be supplied. Completion arrays never duplicate headings or labels. Final/worked models use existing independent release policy; hidden/teacher-with-hidden-fallback data is removed from actual learner JSON before export. The shared visual library contains no completion arrays. C1 steps remain `{id, math, text, alignmentGroup}`.

Existing `q.table` takes precedence as the editable response table. Otherwise the first referenced table uses the same question ID and row:heading keys in the existing host store. Additional tables are givens. No response migration, automatic marking or per-cell handwriting recognition. Paper blanks, typed cells and the activity pen workbook retain existing behaviour. Reordering response table headings/rows requires author review of stored response keys and completion shape; no migration is guessed.

The activity inspector offers reference checkboxes, shared-use locations, description/caption controls, existing figure/image/table editors and separately gated completion-cell editors. Deleting a definition warns about its users and leaves broken references explicit. Invalid drafts remain editable; publication preflight identifies missing/duplicate/unsupported definitions and malformed model shapes. Existing geometry editing capabilities are reused: geometry objects remain JSON-authored where the existing editor has no object controls.

Export embeds required visual image bytes, validates supported image MIME/decoding and static SVG safety, and records `meta.visualAssetManifest` with skill, visual ID, byte count, MIME, source and SHA-256. No external runtime host is added. Relative paths resolve against the authoring document; a local HTTP server is needed when browser file fetch restrictions prevent reading relative files. Uploads use existing data-URI handling. Required assets fail export rather than disappear. Models are inline in the existing Answer Hub; question figures use its existing separate focused workspace, retaining focus and inherited tokens.

Browser DOM/keyboard tests are evidence of those paths, not physical stylus or screen-reader certification. No production lesson publication, graph-linked response change, new geometry application or deployment is authorised by C2.
