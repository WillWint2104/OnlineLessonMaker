# Mathematics question display integration

Approved B1/B1.1 design, implemented as a pure data helper (`core.js`) and bounded host adapter (`host.js`). Build with `node scripts/build-mathematics-question-display.mjs`. The generated block in `lesson-studio.html` is reviewed alongside source; TPMath remains the only math renderer. No independent widget/response store, dependency, storage or automatic marking is introduced.

Canonical `workedSolution.steps[]` has one raw math-only expression, optional explanation/group and a stable step ID. Existing `workedAnswer` and part strings remain supported. Explicit grouped example working reuses the paired primitive. Legacy italic-underscore strings retain their existing interpretation; imported legacy content is not migrated. The diagnostics use the actual TPMath command/function inventory rather than a second command allow-list.

`MathDisplay.issues` provides structural, syntax and dual-source conflict diagnostics. Invalid structured/notation drafts remain loadable/saveable, including the raw import buffer when structural lesson import fails. Publication calls the strict preflight. Matching derived working is normalised with a report and recoverable original import; differing representations are preserved until an explicit author choice. A separate legacy-compatible draft download derives strings without modifying canonical data.

The host adapter uses the existing authoring paths, real JSON importer/exporter, existing Answer Hub controls and paired-example primitive. At short heights the native filter disclosure keeps reading space; its media listener is removed on modal close. A single document-level resize/rAF adapter remeasures current relation groups; it owns no lesson state and retains no old roots. Question/part step editing uses the existing setter/render lifecycle; explicit duplication assigns fresh IDs only to the copied part's steps.

The publication projection removes entire workedSolution objects recursively within questions when worked access is excluded, alongside legacy working. Compatibility strings must be derived only from permitted data for student delivery. The prepared class-session adapter uses derived text for its existing answer payload; no service configuration or deployment changes. Graph questions retain their existing model and reject unsupported ordinary structured working rather than silently ignoring it. Graph engine/source blocks are unchanged.

Legacy scan, actual HTML release matrix, round-trip evidence and native zoom captures are produced by the dedicated verification/capture scripts. Run the focused unit tests with `node --test tests/widgets/mathematics-question-display/core.test.mjs`. Wider gates remain required; these tests do not certify mathematical proof, screen readers or real tablet stylus behaviour.
